# Grace GS — Ghost Theme

A modern, accessible, PWA-ready Ghost theme. Built with vanilla HTML5, CSS3,
and ES6+ JavaScript — no frameworks, no runtime dependencies.

This is the first theme in a planned series of Ghost themes and PWA-first
templates by **AbuEin Technologies**. Originally tailored for **Grace
Governance Solutions Ltd** (the launch deployment), it is released under the
MIT license so others can adopt, fork, and adapt it for their own Ghost
sites.

- **Live deployment:** https://gracegs.com/
- **Author:** Salaheddin AbuEin / AbuEin Technologies — https://abuein.dev/
- **Engine:** Ghost `>= 6.36.0 < 7.0.0`
- **License:** MIT — see [LICENSE](LICENSE)

## Highlights

- Pure HTML/CSS/JS — no framework, no transpilation
- Optional build step: concatenates and minifies CSS/JS for production via `lightningcss` + `terser`
- CSS cascade layers (`reset, tokens, base, utilities, components, overrides, ghost`) with one source of truth per concern
- Light/dark theme via `data-theme` + CSS custom properties, with no-flash boot script
- Ghost custom-font support via `--gh-font-heading` / `--gh-font-body`
- Native ES modules with importmap (`helpers`, `nav`, `pwa`)
- Accessible: skip link, focus-visible rings, `prefers-reduced-motion`, forced-colors mode, semantic HTML, ARIA
- PWA: web app manifest, service worker (cache-first shell, network-first HTML, stale-while-revalidate fonts), offline page, app shortcuts, `web+service` protocol handler, background sync for offline form submits
- Cookie notice, native `<dialog>` contact form (with honeypot + background-sync queue), newsletter signup, FAQ accordion with `<details>`
- Ghost-aware: routes, taxonomies, custom error templates, custom theme settings, `gscan`-clean

## Quick start

### 1. Symlink into a local Ghost instance

```bash
# macOS / Linux
npm run ghost:symlink

# Windows (PowerShell, run as Administrator or with Developer Mode on)
npm run win:symlink
```

Activate the theme: Ghost Admin → Settings → Design → Change theme.

### 2. Run Ghost

```bash
npm run ghost:start       # ghost start
npm run ghost:debug       # ghost run -D (verbose)
npm run ghost:log         # tail logs
npm run ghost:stop
npm run ghost:restart
npm run ghost:update
```

Windows: `win:start` for the Windows install path. Other ghost-cli commands work the same on both.

### 3. Validate with gscan

```bash
npm run scan              # scan working dir
npm run scan:zip          # scan packaged zip on Desktop
```

Combined dev loop:

```bash
npm run dev               # start Ghost + run gscan
```

### 4. Build for production

```bash
npm run build
```

Runs in order: `clean:min` → `build:css` (concat) → `minify:css` (lightningcss) → `minify:js` (terser).

Outputs:
- `assets/css/screen.css` — concatenated bundle in cascade-layer order
- `assets/css/screen.min.css` — minified bundle
- `assets/css/<each>.min.css` — per-file minified CSS (optional, via `minify:css:files`)
- `assets/**/*.min.mjs` — minified JS modules + service worker

`default.hbs` references assets with `hasMinFile='true'`, so Ghost serves the
`.min` versions in production.

### 5. Package for upload

```bash
# macOS / Linux
npm run zip

# Windows
npm run win:zip
```

Uploads via Ghost Admin → Settings → Design → Change theme → Upload theme.

## Customisation

### Custom theme settings (Ghost Admin → Design → Customise)

Declared in `package.json` under `config.custom`, consumed in templates:

| Setting                          | Type    | Default    | Used in                        |
|----------------------------------|---------|------------|--------------------------------|
| `accent_color`                   | color   | `#84cc16`  | `default.hbs` (CSS variable)   |
| `show_title_and_feature_image`   | boolean | `true`     | `post.hbs`, `page.hbs`         |
| `site_layout`                    | select  | `Standard` | `index.hbs`                    |

To add or remove settings, edit `package.json` and reference them in at least
one `.hbs` file (otherwise `gscan` errors).

### Colours

Defined as CSS custom properties in `assets/css/base/tokens.css`. Light is
the default; dark is triggered either by `[data-theme="dark"]` (explicit user
choice, set by the no-flash boot script in `default.hbs`) or by
`prefers-color-scheme: dark` for no-JS users.

The brand colour also lives in:
- `assets/app.webmanifest` (`theme_color`)
- `default.hbs` `<meta name="theme-color">` (per-scheme)
- the inline `<style>` injected from `@custom.accent_color` at render time

### Typography

Headings: `Space Grotesk`. Body: `Inter`. Both fall back to the system font
stack and respect Ghost's custom-font settings via `--gh-font-heading` and
`--gh-font-body` (see `assets/css/ghost/required.css`).

### Content

Marketing content lives in `partials/`. See the file structure above for
which partial owns which section. Posts, pages, authors, and tags come from
Ghost — manage them in Ghost Admin.

### JavaScript modules

`default.hbs` declares an importmap so partials can import named modules:

```html
<script type="importmap">
{
  "imports": {
    "helpers": "/assets/js/mods/helpers.mjs",
    "nav":     "/assets/js/mods/navigation.mjs",
    "pwa":     "/assets/js/mods/pwa.mjs"
  }
}
</script>
```

Entry point: `assets/js/application.mjs` (loaded as `type="module"`).
Enhancements under `assets/js/enhancements/` are dynamically imported by
`pwa.mjs` only if the relevant browser API is detected.

## PWA

- **Manifest:** `assets/app.webmanifest` — full icon set (Android, iOS, Windows 11 tiles), `display: standalone`, `display_override` (`window-controls-overlay`, `fullscreen`, `minimal-ui`), shortcuts (Contact, Products), `web+service` protocol handler, related-application links.
- **Service worker:** `service-worker.mjs` — multi-strategy:
  - Network-first for HTML navigations (with cache fallback to `/`)
  - Cache-first for static assets (CSS, JS, images, fonts)
  - Stale-while-revalidate for fonts (Google + self-hosted)
  - IndexedDB-backed outbox + Background Sync API for queued form submits
- **Offline fallback:** `custom-offline.hbs`
- **Cache name:** `grace-gs-v1` (bump `CACHE_VERSION` in `service-worker.mjs` whenever pre-cached assets change)

To target Microsoft Store / Play Store, validate with [PWABuilder](https://www.pwabuilder.com/).

## Browser support

- Chrome / Edge 123+
- Safari 17.5+
- Firefox 120+

Modern features used: ES modules, importmap, `<dialog>`, CSS cascade layers,
CSS custom properties, `light-dark()` (if adopted), Service Worker, Web Share,
Background Sync, View Transitions, `popover` attribute.

Older browsers degrade gracefully to a static, no-JS page.

## Accessibility

- Skip link to `#main`
- `:focus-visible` ring with `forced-colors` override
- `prefers-reduced-motion` honoured globally
- Native `<dialog>` for the contact modal (browser-handled focus trap, Esc, focus return)
- ARIA: `aria-pressed` on theme toggle, `aria-expanded` + `aria-controls` on mobile toggle, `aria-live="polite"` on cookie notice, `aria-label` on social links
- Keyboard navigation throughout
- Honeypot field for the contact form (`tabindex="-1"`, off-screen, `aria-hidden`)

## SEO

- Semantic HTML5 + ARIA
- `meta description`, `keywords`, `theme-color`, `viewport` in `default.hbs`
- `robots.txt` with explicit rules for major search engines, social crawlers, and AI/LLM crawlers (currently disallowing GPTBot, Google-Extended, CCBot, anthropic-ai, ChatGPT-User, PerplexityBot, cohere-ai)
- `humans.txt`
- Sitemap: Ghost auto-generates at `/sitemap.xml` (referenced from `robots.txt`)
- Open Graph: set the cover image in Ghost Admin → Settings → SEO

## npm scripts reference

### Ghost lifecycle

| Script             | Purpose                                              |
|--------------------|------------------------------------------------------|
| `ghost:start`      | `ghost start -d ~/my/instances/ghost-25`             |
| `ghost:restart`    | `ghost restart`                                      |
| `ghost:stop`       | `ghost stop`                                         |
| `ghost:update`     | `ghost update`                                       |
| `ghost:debug`      | `ghost run -D` (foreground, verbose)                 |

| `win:start`        | Windows variant of `ghost:start`                     |

### Build / package

| Script            | Purpose                                          |
|-------------------|--------------------------------------------------|
| `clean:min`       | Remove all `*.min.*` artefacts under `assets/`   |
| `build:css`       | Concatenate component CSS into `screen.css`      |
| `minify:css`      | Bundle + minify `screen.css` → `screen.min.css`  |
| `minify:css:files`| Minify each component CSS file in place          |
| `minify:js`       | Walk `assets/js/` + `service-worker.mjs`, emit `.min.mjs` |
| `build`           | Full pipeline: clean → build:css → minify:css → minify:js |
| `zip`             | Package as zip (POSIX `zip` CLI)                 |
| `win:zip`         | Package as zip (PowerShell)                      |

### Validation

| Script      | Purpose                                  |
|-------------|------------------------------------------|
| `scan`      | `gscan .` against working directory      |
| `scan:zip`  | `gscan -z` against packaged zip          |
| `dev`       | `ghost:start && scan`                    |

## Contributing

Issues and pull requests are welcome at
https://github.com/sabuein/ghost-themes.

When opening a PR:

1. Run `npm run scan` and make sure `gscan` is clean (0 errors, 0 warnings)
2. Run `npm run build` and ensure both regular and minified files build cleanly
3. Keep the no-framework, no-runtime-dependency constraint — vanilla HTML/CSS/JS only
4. Preserve accessibility (semantic HTML, ARIA, keyboard navigation, `prefers-reduced-motion`, forced-colors)
5. Don't introduce external runtime dependencies beyond what's already in the importmap
